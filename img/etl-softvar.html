Saindo do "puxar relatório manualmente todo dia": um pipeline ETL do ERP para análise, rodando sozinho

O problema de negócio

A rotina de análise financeira dependia de exportar relatórios manualmente do ERP todos os dias — abrir o sistema, gerar o relatório, baixar em Excel, tratar, e só então analisar. Além do tempo perdido, cada exportação manual era uma nova chance de erro humano e não deixava histórico automático de como os dados evoluíam dia a dia.

1. Saindo da lógica de planilha para a lógica de pipeline

Em vez de continuar otimizando a planilha (o que só reduz o sintoma), tratei o problema como uma questão de engenharia de dados: o ERP tem uma API, então a extração pode — e deve — ser automática, agendada e auditável, sem depender de alguém lembrar de rodar o processo.

2. Arquitetura do pipeline

Construí um pipeline de ETL (Extract, Transform, Load) usando GitHub Actions como orquestrador de execução agendada, que consulta a API do ERP, trata e padroniza os dados extraídos, e carrega o resultado em um banco de dados Supabase (Postgres) — criando uma camada de dados estruturada e consultável, em vez de arquivos soltos em pastas.

3. Diagnóstico e resiliência da API

Como a API do ERP nem sempre respondia de forma previsível (limites de requisição, campos inconsistentes entre endpoints), desenvolvi separadamente um diagnóstico em Python/Google Colab para mapear o comportamento da API antes de automatizar — identificando quais chamadas eram estáveis o suficiente para rodar sem supervisão e quais precisavam de tratamento de erro específico.

4. Da automação à análise

Com os dados chegando de forma confiável e estruturada no banco, o trabalho analítico deixou de competir por tempo com o trabalho operacional de "buscar o dado" — permitindo direcionar o esforço para interpretação e apresentação executiva, em vez de extração manual repetitiva.

Impacto e próximos passos

A automação eliminou uma tarefa manual diária do fluxo de trabalho e criou uma base de dados histórica e consultável que antes não existia — abrindo caminho para análises de série temporal que dependiam de dado acumulado ao longo do tempo, algo inviável quando a extração era manual e não versionada.

Ferramentas Utilizadas no Projeto

  • GitHub Actions (orquestração e agendamento)
  • Python (extração e tratamento de dados)
  • Supabase / PostgreSQL (camada de dados)
  • API REST (ERP)
  • Google Colab (diagnóstico e prototipagem)
